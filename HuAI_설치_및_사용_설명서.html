HuAI COLLAB CHATROOM SYSTEM

설치 및 사용 설명서

텔레그램 방 하나를 AI 업무 지휘소로 만드는 시스템입니다. 기술을 몰라도 이 문서 순서대로 따라 하면 설치부터 실제 사용까지 끝납니다. 최신 갱신일 2026-08-23.

00 개요

이 시스템이 뭔가요

텔레그램 비공개 그룹방 하나가 "AI 업무 지휘소"가 됩니다. 방에서 사람 말투로 지시하면 AI(Claude·Codex)가 실제로 파일을 만들고 고치고, 결과를 방에 보고하고, 방장이 승인 버튼을 눌러야 최종 확정됩니다.

HuAI = 텔레그램 방(사람) + LeaderBot(요청 정리·승인 라우팅) + ClaudeBot·CodexBot(실행) + AuditBot(독립 검증) + Supabase(공식 기록) + local-gateway(내 PC에서 실제 실행)가 함께 돌아가는 Human-AI 협업 운영 시스템입니다.

시작 전 체크리스트

아래 5가지가 필요합니다. 전부 무료로 시작할 수 있습니다.

  • ✓
    Windows PC 1대 — AI가 실제로 코드를 실행하는 곳. 설치 후에는 이 PC가 켜져 있어야 시스템이 돌아갑니다.
  • ✓
    Node.js — 이 시스템 자체가 Node.js로 만들어져 있습니다.
  • ✓
    Supabase 계정 — 작업 기록·승인 이력·산출물 주소를 저장하는 DB. 무료 플랜으로 충분합니다.
  • ✓
    Telegram 계정 + 봇 4개 — 사람이 지시하고 결과를 받는 화면.
  • ✓
    Vercel 계정 — AI가 만든 웹 결과물을 인터넷에 올려 폰에서 열어보는 용도. 무료 플랜으로 충분합니다.
예상 소요 시간: 처음이면 30~50분 정도 걸립니다. 대부분 "계정 만들고 값 복사해서 붙여넣기"입니다. 탭 01 → 02 → 03 순서로 그대로 따라가면 됩니다.
01 설치

PC 준비 — Node.js와 시스템 파일

이 PC에 시스템이 돌아갈 재료를 받는 단계입니다.

1단계 — Node.js 설치

  1. nodejs.org에 접속합니다.
  2. "LTS"라고 적힌 버전을 다운로드합니다(권장 버전).
  3. 설치 파일을 실행하고 나오는 화면에서 전부 "Next"만 눌러 설치를 끝냅니다.

확인: Win 키 → PowerShell 입력 → 엔터로 엽니다. 그 창에 아래를 치고 엔터:

node --version

v24로 시작하는 숫자가 나오면 성공입니다.

2단계 — 시스템 파일 받기

git을 쓸 줄 알면:

git clone https://github.com/SUNWOONGKYU/HuAIChatroomSystem.git C:\Dev\HuAIChatroomSystem

git을 모르면(ZIP으로):

  1. GitHub 저장소 페이지 접속 → 초록색 Code 버튼 → Download ZIP
  2. 다운로드된 zip을 오른쪽 클릭 → "압축 풀기" → C:\Dev\HuAIChatroomSystem 같은 기억하기 쉬운 경로에 풀기 (한글·공백 없는 경로 권장)

3단계 — 필요한 부품 설치 + 빌드

PowerShell에서 방금 그 폴더로 이동한 뒤 아래 3줄을 순서대로 칩니다.

cd C:\Dev\HuAIChatroomSystem
npm install
npm run build
npm install은 1~3분 걸립니다. 중간에 빨간 글씨가 좀 보여도 마지막에 에러 없이 끝나면 괜찮습니다.
02 설치

Supabase 프로젝트 만들기

이 시스템은 "누가 뭘 시켰고, 누가 승인했고, 결과물이 뭔지"를 전부 DB에 기록합니다. 텔레그램 메시지는 화면일 뿐이고, 공식 기록은 여기(Supabase)입니다.

1
가입 · 프로젝트 생성

supabase.com 접속 → 회원가입(구글 계정 가능) → New Project → 이름·비밀번호(꼭 메모)·지역 입력 → Create

2
URL·키 복사

왼쪽 톱니바퀴(Project Settings) → API → Project URL과 service_role 키를 메모장에 복사

3
DB 스키마 적용

왼쪽 메뉴 SQL Editor → New query → supabase/schema.sql 전체 내용을 복사해 붙여넣고 Run

⚠️ service_role 키는 이 시스템 전체를 조작할 수 있는 열쇠입니다. 남에게 보여주거나 인터넷(GitHub 등)에 올리면 안 됩니다.
03 설치

텔레그램 연결, 설정 채우기, 실행

봇 4개를 만들고, 값을 한 파일에 모으고, 서비스를 켜는 마지막 구간입니다.

4단계 — 텔레그램 봇 4개 만들기

이 시스템은 봇 1개가 아니라 4개(소대장·클로드·코덱스·감사관 역할)를 씁니다.

  1. 텔레그램에서 BotFather(공식 파란 체크 봇)를 검색해 대화를 엽니다.
  2. /newbot 전송 → 봇 이름(아무거나) → 봇 username(반드시 bot으로 끝나야 함) 순서로 입력합니다.
  3. 성공하면 긴 토큰 문자열을 줍니다 — 메모장에 복사하고 어느 역할인지 표시해둡니다.
  4. 이 과정을 4번 반복: LeaderBot(소대장) · ClaudeBot · CodexBot · AuditBot(감사)
⚠️ 4개는 반드시 서로 다른 봇(다른 토큰)이어야 합니다. 봇 1개로 4역할을 흉내내는 방식이 아닙니다.

5단계 — 비공개 그룹 만들고 봇 초대

  1. 텔레그램에서 새 그룹(비공개)을 만들고 봇 4개를 전부 초대합니다.
  2. 그룹 chat_id 알아내기: 그룹에 아무 메시지("테스트")를 보낸 뒤, 브라우저에서 https://api.telegram.org/bot<봇토큰>/getUpdates 를 엽니다. "chat":{"id": 뒤에 나오는 숫자(보통 -로 시작)가 chat_id입니다.
  3. 내 user_id 알아내기: 텔레그램에서 @userinfobot을 검색해 아무 메시지나 보내면 숫자 id를 알려줍니다. 이 값이 "방장 권한"의 기준입니다 — 승인 버튼은 이 id를 가진 사람만 누를 수 있습니다.

6단계 — 설정 파일 채우기

  1. .env.operation.example 파일을 복사해 이름을 .env.operation.local로 바꿉니다.
  2. 메모장으로 열어 아래 표의 값을 채웁니다.
항목어디서 가져오는 값
SUPABASE_URL탭 02의 Project URL
SUPABASE_SERVICE_ROLE_KEY탭 02의 service_role 키
BOT_SERVICE_TELEGRAM_CHAT_ID위 그룹 chat_id
BOT_SERVICE_OWNER_TELEGRAM_USER_ID위 내 user_id
BOT_SERVICE_PLATOON/CLAUDE/CODEX/AUDITOR_BOT_TOKEN봇 4개 토큰 (각각)

BOT_SERVICE_RECEIVE_MODE=polling 인지 확인합니다(없으면 추가) — 공개 인터넷 주소·터널 설정 없이 이 PC에서 텔레그램으로 직접 연결됩니다, 가장 간단한 방식입니다. LOCAL_GATEWAY_ALLOWED_ROOTS도 2단계에서 받은 폴더 경로로 맞춥니다.

⚠️ .env.operation.local은 절대 GitHub에 올리거나 남에게 보내면 안 됩니다. 비밀번호나 다름없는 값들이 들어있습니다.

7단계 — 이 방을 시스템에 등록하기

방 고유 번호(UUID)를 만듭니다:

node -e "console.log(crypto.randomUUID())"

아래 명령을 실제 값으로 바꿔 실행합니다:

node scripts/generate-supabase-room-seed.mjs --room-id <room-id> --chat-id <chat-id> --owner-id <owner-id> --project-path "C:\Dev\HuAIChatroomSystem"

출력된 SQL 전체를 복사해 Supabase SQL Editor에 붙여넣고 Run 합니다.

8단계 — 서비스 실행

PowerShell 창을 2개 엽니다(각각 계속 띄워둡니다).

창1
bot-service
cd C:\Dev\HuAIChatroomSystem
node dist/apps/bot-service/src/cli.js
창2
local-gateway
cd C:\Dev\HuAIChatroomSystem
node dist/apps/local-gateway/src/cli.js

두 창 모두 멈추지 않고 계속 떠 있는 상태면 정상입니다. PC가 켜져 있는 동안 계속 열려 있어야 시스템이 작동합니다.

9단계 — 설치 확인

텔레그램 그룹방에서:

@my_leader_chatroom_bot 안녕

LeaderBot이 몇 초 안에 반응하면 설치 성공입니다. 반응이 없으면 탭 05 "문제 해결"을 봅니다.

04 사용

실제로 이렇게 씁니다

설치가 끝난 뒤, 방에서 AI에게 일을 시키고 승인하는 흐름입니다.

AI에게 일 시키기

봇을 지목해서 말하면 접수됩니다(그냥 하는 말에는 시스템이 관여하지 않습니다 — 사람끼리 대화하는 공간이기도 합니다).

@my_leader_chatroom_bot 버튼 오류 원인을 찾아 수정해줘

LeaderBot이 이걸 목적·범위·완료 조건을 갖춘 "작업 제안"으로 정리해 방에 올립니다.

승인하기

실행수정반려 검증보완완료
버튼의미
실행제안을 승인하고 실제 작업을 시작합니다
수정제안 내용을 다시 다듬어달라고 요청합니다
반려이 제안은 진행하지 않습니다
검증AuditBot 재검증을 요청합니다
보완작업자에게 보완을 요청합니다
완료방장이 최종 완료 승인합니다(현황판에서)
자동허용 — 파일을 전혀 안 바꾸는 조회·분석·설명성 지시는 "실행" 버튼 자체가 뜨지 않고 바로 시작됩니다(방에 "🟢 자동 시작" 안내만 뜹니다). 판단이 애매하면 시스템은 항상 안전한 쪽(승인 필요)으로 처리합니다.

결과 확인하기

작업이 끝나면 방에 결과가 옵니다. 300자가 넘는 긴 보고는 앞부분만 방에 오고 [전문 보기] 버튼이 붙습니다 — 눌러서 현황판에서 전체를 봅니다. 현황판은 방에 고정된 링크나 /tasks 명령으로 엽니다.

완료 승인하기

작업이 끝나면 현황판에서 완료 승인을 합니다(방 안에는 완료 승인 버튼이 따로 없습니다).

퀴즈가 뜰 수 있습니다 — 파일을 실제로 바꾼 작업은 완료 승인 전에 "뭐가 바뀌었는지 이해했는지" 확인하는 객관식 3문항이 먼저 나옵니다(인지부채 방지 장치). 통과해야 완료 승인 버튼이 나옵니다.
웹 페이지를 만든 작업이라면 — 완료 승인 전에는 산출물 링크가 "프리뷰"(아직 정식 주소 아님) 상태입니다. 완료 승인을 누르는 순간 그 링크가 정식(프로덕션) 주소로 바뀝니다 — 승인 전에 결과물이 먼저 공개돼버리는 걸 막기 위한 설계입니다.

그 밖의 명령어

/tasks                작업 목록
/task <task_id>       작업 하나 상세
/search <단어>         작업 검색
/trace <task_id>      이벤트·산출물·검증 이력
@audit_chatroom_bot 이 작업을 보안 검토해줘   (감사관에게 직접 요청)
05 FAQ

문제가 생기면

처음 설치할 때 가장 자주 걸리는 것부터 정리했습니다.

증상원인 · 해결
봇이 아무 반응이 없다탭 03의 두 PowerShell 창이 열려 있는지 확인. 닫혀 있으면 다시 실행
npm install에서 멈추거나 에러인터넷 연결 확인 후 다시 실행. 안 되면 Node.js를 v24 LTS로 재설치
창을 열자마자 바로 꺼진다(에러).env.operation.local에 빈 값이 없는지 확인(특히 봇 토큰 4개, Supabase URL/키)
"봇 여러 개가 같은 토큰" 비슷한 에러봇 4개가 진짜 서로 다른 토큰인지 확인
승인 버튼을 눌러도 반응이 늦다정상입니다 — 실제 AI 실행은 몇 초~몇 분 걸립니다. 방에 "⏳ 작업 중" 표시가 주기적으로 올라옵니다
Supabase SQL 실행에서 에러supabase/schema.sql 전체를 빠짐없이 붙여넣었는지 확인(일부만 붙여넣으면 실패)
이 표에 없는 문제는 탭 06 부록의 GITHUB_QUICKSTART.md(더 기술적인 버전)와 OPERATION_STATUS.md(현재 알려진 이슈 목록)를 참고하세요.
