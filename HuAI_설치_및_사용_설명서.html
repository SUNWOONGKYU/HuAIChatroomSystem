이 시스템을 이루는 조각들이 정확히 뭘 하는지입니다.

방
텔레그램 방

사람이 지시하고 결과를 받는 화면. 이 시스템의 유일한 사용자 인터페이스입니다.

L
LeaderBot(리더)

사람 말을 읽고 "이건 질문인지 작업인지" 먼저 판단합니다. 작업이면 목적·범위·완료조건을 갖춘 제안으로 정리해 방에 올립니다.

C
ClaudeBot · CodexBot

실제로 코드를 읽고 파일을 만들거나 고치는 실행자입니다. Gemini 웹은 계획·검토·텍스트 결과에 사용되며 로컬 파일을 직접 수정하지 않습니다.

A
AuditBot(감사)

실행자와 다른 엔진이 결과물을 독립적으로 다시 검토합니다 — 만든 사람이 자기 결과를 자기가 검사하지 않게 하기 위해서입니다.

B
bot-service

텔레그램과 이 시스템을 연결하는 통로. 누가 말했는지 확인하고, 권한을 검사하고, 답을 다시 텔레그램으로 보냅니다.

G
local-gateway

내 PC 안에서 실제로 명령을 실행하는 부분. 방마다 등록된 프로젝트 폴더인지 먼저 확인한 뒤에만 실행을 넘깁니다 — 등록 안 된 경로면 아예 실행을 거부합니다. 다만 OS 수준 격리(샌드박스)까지는 아니고, 그 폴더 안에서 AI가 실제로 뭘 바꾸는지는 되돌리는 기능이 따로 없습니다 — 중요한 폴더라면 직접 git으로 버전 관리해두는 걸 권장합니다.

D
Supabase

"누가 뭘 시켰고 누가 승인했는지"를 남기는 공식 기록 창고. 텔레그램 메시지가 지워져도 여기 기록은 남습니다.

V
Vercel

AI가 만든 웹페이지를 인터넷 주소로 올려 폰에서 바로 열어볼 수 있게 하는 곳.

시작 전 체크리스트

아래 6가지가 필요합니다. Windows PC·Supabase·Telegram·Vercel은 무료로 시작할 수 있습니다. Claude Code·Codex는 별도 유료 구독이 필요합니다 — 다만 호출 한 번마다 요금이 붙는 API 방식이 아니라 월 정액 구독이고, 이 시스템은 그 구독을 화면 없이 뒤에서 돌리는 헤드리스 모드로 씁니다.

  • ✓
    Windows PC 1대 — AI가 실제로 코드를 실행하는 곳. 설치 후에는 이 PC가 켜져 있어야 시스템이 돌아갑니다.
  • ✓
    Node.js — 이 시스템 자체가 Node.js로 만들어져 있습니다.
  • ✓
    Supabase 계정 — 작업 기록·승인 이력·산출물 주소를 저장하는 DB. 무료 플랜으로 충분합니다.
  • ✓
    Telegram 계정 + 봇 4개 — 사람이 지시하고 결과를 받는 화면.
  • ✓
    Vercel 계정 + Vercel CLI — AI가 만든 웹 결과물을 인터넷에 올려 폰에서 열어보는 용도. 무료 플랜으로 충분하고, CLI 설치·로그인은 탭 03의 8단계에서 합니다.
  • ✓
    Claude Code · Codex 로그인 — 실제로 파일을 읽고 고치는 실행 엔진입니다. Gemini 웹은 계획·검토·텍스트 결과용 웹 세션으로 사용되며 로컬 파일을 직접 수정하지 않습니다.
예상 소요 시간: 처음이면 30~50분 정도 걸립니다. 대부분 "계정 만들고 값 복사해서 붙여넣기"입니다. 탭 01 → 02 → 03 순서로 그대로 따라가면 됩니다.
01 개발 도구 설치

개발 도구 설치 — Node.js와 시스템 파일 받기

이 PC에 시스템이 돌아갈 재료를 받는 단계입니다.

1단계 — Node.js 설치

  1. nodejs.org에 접속합니다.
  2. "LTS"라고 적힌 버전을 다운로드합니다(권장 버전).
  3. 설치 파일을 실행하고 나오는 화면에서 전부 "Next"만 눌러 설치를 끝냅니다.

확인: Win 키 → PowerShell 입력 → 엔터로 엽니다. 그 창에 아래를 치고 엔터:

node --version

v24로 시작하는 숫자가 나오면 성공입니다.

2단계 — 시스템 파일 받기

git을 쓸 줄 알면:

git clone https://github.com/SUNWOONGKYU/HuAIChatroomSystem.git C:\Dev\HuAIChatroomSystem

git을 모르면(ZIP으로):

  1. GitHub 저장소 페이지 접속 → 초록색 Code 버튼 → Download ZIP
  2. 다운로드된 zip을 오른쪽 클릭 → "압축 풀기" → C:\Dev\HuAIChatroomSystem 같은 기억하기 쉬운 경로에 풀기 (한글·공백 없는 경로 권장)

3단계 — 필요한 부품 설치 + 빌드

PowerShell에서 방금 그 폴더로 이동한 뒤 아래 3줄을 순서대로 칩니다.

cd C:\Dev\HuAIChatroomSystem
npm install
npm run build
npm install은 1~3분 걸립니다. 중간에 빨간 글씨가 좀 보여도 마지막에 에러 없이 끝나면 괜찮습니다.
02 DB 준비

Supabase 프로젝트 만들기

이 시스템은 "누가 뭘 시켰고, 누가 승인했고, 결과물이 뭔지"를 전부 DB에 기록합니다. 텔레그램 메시지는 화면일 뿐이고, 공식 기록은 여기(Supabase)입니다.

1
가입 · 프로젝트 생성

supabase.com 접속 → 회원가입(구글 계정 가능) → New Project → 이름·비밀번호(꼭 메모)·지역 입력 → Create

2
URL·키 복사

왼쪽 톱니바퀴(Project Settings) → API → Project URL과 service_role 키를 메모장에 복사

3
DB 스키마 적용

탭 01에서 받은 내 PC 폴더(C:\Dev\HuAIChatroomSystem) 안의 supabase\schema.sql 파일을 메모장으로 열어 전체 선택(Ctrl+A)·복사 → Supabase 왼쪽 메뉴 SQL Editor → New query → 붙여넣고 Run

⚠️ service_role 키는 이 시스템 전체를 조작할 수 있는 열쇠입니다. 남에게 보여주거나 인터넷(GitHub 등)에 올리면 안 됩니다.
03 텔레그램봇 만들기

텔레그램 연결, 설정 채우기, 실행

봇 4개를 만들고, 값을 한 파일에 모으고, 서비스를 켜는 마지막 구간입니다.

4단계 — 텔레그램 봇 4개 만들기

이 시스템은 봇 1개가 아니라 4개(리더·클로드·코덱스·감사관 역할)를 씁니다.

  1. 텔레그램에서 BotFather(공식 파란 체크 봇)를 검색해 대화를 엽니다.
  2. /newbot 전송 → 봇 이름(아무거나) → 봇 username(반드시 bot으로 끝나야 함) 순서로 입력합니다.
  3. 성공하면 긴 토큰 문자열을 줍니다 — 메모장에 복사하고 어느 역할인지 표시해둡니다.
  4. 이 과정을 4번 반복: LeaderBot(리더) · ClaudeBot · CodexBot · AuditBot(감사)
⚠️ 4개는 반드시 서로 다른 봇(다른 토큰)이어야 합니다. 봇 1개로 4역할을 흉내 내는 방식이 아닙니다.

5단계 — 비공개 그룹 만들고 봇 초대

쉽게 말하면: 방을 만들고, 그 "방 번호"와 "내 번호"를 시스템에 알려주는 단계입니다 — 시스템이 "어느 방에서, 누가" 말했는지 구별하는 데 씁니다.

  1. 텔레그램에서 새 그룹(비공개)을 만들고 봇 4개를 전부 초대합니다.
  2. 그룹 chat_id(방 번호) 알아내기: 그룹에서 봇을 지목해 @내봇이름 테스트처럼 메시지를 보냅니다 — 텔레그램 봇은 기본적으로 그룹의 일반 대화를 못 읽기 때문에(개인정보 보호 설정), 그냥 "테스트"라고만 보내면 getUpdates에 잡히지 않습니다. 보낸 뒤 브라우저에서 https://api.telegram.org/bot<봇토큰>/getUpdates 를 엽니다. <봇토큰> 자리에는 4개 중 아무 봇의 토큰이나 넣으면 됩니다(같은 방이라 어느 봇으로 봐도 chat_id는 같습니다). 헷갈리면 LeaderBot 토큰을 쓰세요. "result":[]처럼 비어 있으면 봇을 한 번 더 지목해 보내고 새로고침하세요. "chat":{"id": 뒤에 나오는 숫자(보통 -로 시작)가 chat_id입니다.
  3. 내 user_id(내 번호) 알아내기: 텔레그램에서 @userinfobot을 검색해 아무 메시지나 보내면 숫자 id를 알려줍니다. 이 값이 "방장 권한"의 기준입니다 — 협업 운영센터의 결정 버튼은 이 id를 가진 사람만 사용할 수 있습니다.

6단계 — 설정 파일 채우기

쉽게 말하면: 지금까지 여기저기서 복사해둔 값들을 파일 한 장에 모아 붙여넣는 단계입니다. 아래 표는 "이 빈칸엔 이 값" 대응표일 뿐이니, 항목 이름이 낯설어도 왼쪽 줄이 어디서 나온 값인지만 따라가면 됩니다.

  1. .env.operation.example 파일을 복사해 이름을 .env.operation.local로 바꿉니다.
  2. 메모장으로 열어 아래 표의 값을 채웁니다.
항목어디서 가져오는 값
SUPABASE_URL탭 02의 Project URL
SUPABASE_SERVICE_ROLE_KEY탭 02의 service_role 키
BOT_SERVICE_TELEGRAM_CHAT_ID위 그룹 chat_id(방 번호)
BOT_SERVICE_OWNER_TELEGRAM_USER_ID위 내 user_id(내 번호)
BOT_SERVICE_LEADER/CLAUDE/CODEX/AUDITOR_BOT_TOKEN봇 4개 토큰 (각각) — LEADER=LeaderBot(리더) · CLAUDE=ClaudeBot · CODEX=CodexBot · AUDITOR=AuditBot(감사)
BOT_SERVICE_LEADER/CLAUDE/CODEX/AUDITOR_BOT_USERNAME봇 4개의 사용자명 (각각, 매핑은 위 행과 동일) — 5단계에서 지은 이름에서 앞의 @를 뺀 것. 예: LeaderBot을 @bloom_leader_bot으로 지었다면 bloom_leader_bot
⚠️ ..._BOT_USERNAME 4개는 반드시 채워야 합니다. 비워두면 7단계에서 missing-env:BOT_SERVICE_LEADER_BOT_USERNAME 같은 영어 오류로 멈추고, 예시값(your_leader_bot)을 그대로 두면 오류 없이 잘못된 이름이 그대로 등록됩니다.

BOT_SERVICE_RECEIVE_MODE=polling 인지 확인합니다(없으면 추가) — 이렇게만 해두면 별도 인터넷 주소 설정 없이 이 PC가 텔레그램과 알아서 연결됩니다 — 가장 간단한 방식입니다. LOCAL_GATEWAY_ALLOWED_ROOTS도 2단계에서 받은 폴더 경로로 맞춥니다(이 시스템이 손댈 수 있는 폴더를 정해두는 항목입니다).

⚠️ .env.operation.local은 절대 GitHub에 올리거나 남에게 보내면 안 됩니다. 비밀번호나 다름없는 값들이 들어있습니다.

7단계 — 이 방을 시스템에 등록하기

쉽게 말하면: "이 텔레그램 방 = 이 컴퓨터의 이 폴더"라고 시스템에 한 번 알려주는 단계입니다. 아래 명령어를 그대로 복사해서 붙여넣으면 됩니다 — 내용을 몰라도 됩니다.

먼저 이 방만의 고유 이름표(UUID, 아무 뜻 없는 랜덤 번호)를 하나 만듭니다:

node -e "console.log(crypto.randomUUID())"

화면에 3f2b9c1e-... 같은 긴 문자열이 하나 나옵니다. 이걸 복사해 두세요.

아래 명령의 <...> 세 자리를 실제 값으로 바꿔 실행합니다:

바꿀 자리넣을 값
<room-id>바로 위에서 만든 UUID 문자열
<chat-id>5단계에서 알아낸 그룹 chat_id (보통 -로 시작하는 숫자)
<owner-id>5단계에서 알아낸 내 user_id 숫자
node --env-file=.env.operation.local scripts/generate-supabase-room-seed.mjs --room-id <room-id> --chat-id <chat-id> --owner-id <owner-id> --project-path "C:\Dev\HuAIChatroomSystem"
⚠️ 맨 앞의 --env-file=.env.operation.local을 빼면 안 됩니다. 이게 없으면 6단계에서 채운 값을 못 읽어 missing-env:BOT_SERVICE_LEADER_BOT_USERNAME 오류로 멈춥니다.

출력된 SQL 전체를 복사해 Supabase SQL Editor에 붙여넣고 Run 합니다.

8단계 — Claude Code / Codex / Gemini 웹 / Vercel 확인

이 PC에는 Claude Code·Codex가 설치·로그인돼 있어야 파일 수정 작업이 실행됩니다. Gemini 웹은 전용 Chrome 세션에 로그인돼 있어야 계획·검토·텍스트 결과를 받을 수 있습니다. 웹 페이지를 만드는 작업을 쓸 거라면 Vercel CLI도 필요합니다.

먼저 이미 깔려 있는지 확인합니다. PowerShell에서:

claude --version
codex --version
agy --version
vercel --version

버전 숫자가 나오면 설치는 끝난 것이니 로그인 여부만 확인하고 넘어갑니다. 인식할 수 없는 명령 류의 오류가 나오는 쪽만 아래대로 설치합니다.

도구설치로그인
Claude Codenpm install -g @anthropic-ai/claude-codeclaude 를 실행하면 브라우저가 열리며 로그인 안내가 나옵니다
Codex CLInpm install -g @openai/codexcodex login 실행 후 브라우저에서 ChatGPT 계정으로 로그인
Gemini 웹자동화 전용 Chrome(CDP 9222) 세션gemini.google.com에 운영자가 직접 로그인
Vercel CLInpm install -g vercelvercel login 실행 후 브라우저에서 로그인

공식 안내: Claude Code 문서 · Codex CLI 저장소 · Gemini 웹. 로그인·설치 방법은 각 서비스의 최신 안내를 따르세요.

방금 설치했는데도 인식할 수 없는 명령 오류가 그대로 나오면, 지금 열려 있는 PowerShell 창을 닫고 새로 여세요 — 설치 직후엔 이미 열려 있던 창이 새로 생긴 명령어 경로를 못 읽는 경우가 흔합니다.
파일 수정 작업은 Claude Code·Codex가 실행합니다. Gemini 웹은 전용 Chrome 세션으로 계획·검토·텍스트 결과를 처리하며 로컬 파일을 직접 수정하지 않습니다. 실행 엔진 한도가 발생하면 시스템 정책에 따라 가능한 엔진으로 인계합니다.

9단계 — 서비스 실행

PowerShell 창을 1개 열고 아래를 실행합니다. 이 명령 하나가 .env.operation.local을 읽어들이고 bot-service와 local-gateway 둘 다 띄워주며, 하나가 죽으면 자동으로 다시 올립니다.

cd C:\Dev\HuAIChatroomSystem
node scripts/start-services.mjs

창에 두 서비스가 떴다는 로그가 나오고 멈추지 않고 계속 떠 있으면 정상입니다. PC가 켜져 있는 동안 이 창이 계속 열려 있어야 시스템이 작동합니다.

⚠️ node dist/apps/bot-service/src/cli.js처럼 서비스를 직접 실행하지 마세요. 그렇게 하면 .env.operation.local이 읽히지 않아서, 파일을 아무리 정확히 채웠어도 창이 열리자마자 missing-env:SUPABASE_URL 같은 오류를 내고 꺼집니다. 반드시 위의 scripts/start-services.mjs로 켜세요.
PC를 재부팅했거나 이 창을 실수로 닫았다면, 시스템이 저절로 다시 켜지지 않습니다. PowerShell을 새로 열고 위 두 줄(cd C:\Dev\HuAIChatroomSystem → node scripts/start-services.mjs)을 다시 실행해야 합니다.
(선택) 재부팅해도 자동으로 다시 켜지게 하려면 — PowerShell에서 scripts/install-autostart.ps1을 한 번만 실행해두면, 다음부터는 이 PC에 로그인할 때마다(1분 후) 시스템이 자동으로 켜집니다. 매번 위 창을 직접 열지 않아도 됩니다.
백업은 자동으로 됩니다 — 방마다 쌓인 작업·승인·산출물 기록은 시스템이 뜬 상태에서 6시간마다 자동으로 스냅샷 파일로 백업됩니다. 로그 파일도 너무 커지지 않게 자동으로 정리(회전)됩니다. 만에 하나 데이터를 되돌려야 할 때는 GITHUB_QUICKSTART.md의 "방 백업·복구" 항목을 참고하세요 — 되돌리기는 사람이 PC 앞에서 직접 판단해서 실행하는 절차입니다.

10단계 — 설치 확인

텔레그램 그룹방에서:

@<LeaderBot_이름> 안녕
<LeaderBot_이름>은 그대로 치는 게 아니라 자리표시자입니다. 5단계에서 본인이 BotFather로 지은 LeaderBot 사용자명으로 바꿔 쓰세요 — 텔레그램 봇 이름은 전 세계에서 하나뿐이라 남의 문서에 있는 이름을 그대로 쓸 수 없습니다. 이 설명서에서 <…_이름> 꼴은 전부 같은 뜻입니다.

LeaderBot이 몇 초 안에 반응하면 설치 성공입니다. 반응이 없으면 탭 05 "문제 해결"을 봅니다.

11단계 — 여러 방 동시 운영하기 (선택)

봇 4개를 그대로 두고, 완전히 다른 프로젝트 폴더를 쓰는 방을 하나 더 운영하고 싶을 때만 합니다. BotFather에서 새 봇을 또 만들 필요는 없습니다 — 같은 봇 4개를 새 방에 다시 초대하면 됩니다.

  1. 4~7단계를 새 방 기준으로 그대로 반복합니다(같은 봇 4개 초대 → 새 chat_id·room UUID 확인 → generate-supabase-room-seed.mjs 재실행). 이때 출력된 SQL 안에서 huai_gateway_instances에 들어가는 gateway_id 값을 따로 복사해 둡니다 — 직접 만드는 값이 아니라 스크립트가 방 UUID로 정해서 내놓는 값입니다.
  2. .env.operation.local의 LOCAL_GATEWAY_EXTRA_INSTANCES에 한 줄 추가합니다: 라벨|위에서 복사한 gateway_id|안 쓰는 포트 번호|그 방의 프로젝트 폴더 경로. 방이 여러 개면 세미콜론(;)으로 이어 붙입니다.
  3. 서비스를 node scripts/start-services.mjs가 아니라 node scripts/restart-operation-services-from-live-env.mjs로 재시작해야 추가한 방이 같이 뜹니다 — 9단계의 명령은 기본 방 하나만 띄웁니다.
⚠️ 포트 번호는 이미 쓰고 있는 값(기본 8797 등)과 겹치면 안 됩니다. 방마다 프로젝트 폴더도 서로 겹치지 않아야 합니다 — 한 방의 실행이 다른 방의 폴더를 건드리지 않게 막는 장치입니다.
04 AI 작업 시키기

실제로 이렇게 씁니다

설치가 끝난 뒤, 방에서 AI에게 일을 시키고 협업 운영센터에서 결정하는 흐름입니다.

AI에게 일 시키기

봇을 지목해서 말하면 접수됩니다(그냥 하는 말에는 시스템이 관여하지 않습니다 — 사람끼리 대화하는 공간이기도 합니다).

@<LeaderBot_이름> 버튼 오류 원인을 찾아 수정해줘

LeaderBot이 이걸 목적·범위·완료 조건을 갖춘 "작업 제안"으로 정리해 방에 올립니다.

승인하기

Telegram은 작업 지시·접수·진행 알림과 협업 운영센터 링크를 제공합니다. 봇 메뉴의 /center를 선택하면 현재 방·포럼 주제의 협업 운영센터가 열립니다. 방장 승인·통제는 협업 운영센터에서만 처리합니다. 예전 고정 협업 운영센터 메시지는 사용하지 않습니다.

실행수정반려 전문 보기협업 운영센터 열기승인보완 요청
버튼어디서 누르나의미
작업 지시·알림텔레그램 방작업을 지시하고 접수·진행·결과 알림을 받습니다
전문 보기텔레그램 방방에 앞부분만 온 긴 보고에 붙습니다. 누르면 협업 운영센터가 열리며 전체 내용을 봅니다
/center텔레그램 봇 메뉴현재 방·포럼 주제의 협업 운영센터를 엽니다
승인·수정·반려·보완·취소협업 운영센터제안·중간 결과·완료에 대한 방장 결정을 처리합니다
방에는 상태를 바꾸는 결정 버튼이 없습니다. 제안 승인·수정·반려부터 중간 승인, 완료 승인·보완·취소까지 모든 방장 결정은 협업 운영센터에서 합니다. 방에서 아무리 찾아도 없는 게 정상입니다. 협업 운영센터의 완료 버튼 이름은 「완료 승인」이 아니라 그냥 「승인」입니다.
자동허용 — 파일을 전혀 안 바꾸는 조회·분석·설명성 지시는 "실행" 버튼 자체가 뜨지 않고 바로 시작됩니다(방에 "🟢 자동 시작" 안내만 뜹니다). 판단이 애매하면 시스템은 항상 안전한 쪽(승인 필요)으로 처리합니다.
협업 운영센터를 열면 승인 필요 · 진행 중 · 대기 · 중단 · 완료 5개 탭으로 작업이 나뉘어 있습니다. 작업 카드를 누르면 상세 화면이 열리고, 결과물이 있으면 「결과물」 항목에 링크로 뜹니다.

결과 확인 · 완료 승인하기

작업이 끝나면 방에 결과가 옵니다. 300자가 넘는 긴 보고는 앞부분만 방에 오고 [전문 보기] 버튼이 붙습니다 — 눌러서 협업 운영센터에서 전체를 봅니다. 결과물이 있으면 협업 운영센터 상세의 「결과물」 목록에 링크로 표시되니, 먼저 확인한 뒤 [승인]을 누르세요.

퀴즈가 뜰 수 있습니다 — 배포·삭제·권한/인증·환경변수·시크릿·중요 설정·DB 스키마 변경처럼 고위험 작업만 완료 승인 전에 객관식 3문항을 요구합니다. 조회·분석·설명·검토와 단순 저위험 파일 변경은 퀴즈 없이 승인할 수 있습니다.
synthetic 계획 테스트 — npm run build 후 node --test dist/apps/bot-service/test/synthetic-leader-planning-webhook.test.js를 실행합니다. 가상 방의 방장 5001·참여자 9001 4턴과 가짜 webhook/fetch만 사용하며 실제 Telegram/Supabase에 쓰지 않습니다. 게임의 30초 생존은 테스트 훅이고 공개 URL 클릭 여정은 환경 제약으로 미검증입니다.
웹 페이지를 만든 작업이라면 — 완료 승인 전에는 산출물 링크가 "프리뷰"(아직 정식 주소 아님) 상태입니다. 완료 승인을 누르는 순간 그 링크가 정식(프로덕션) 주소로 바뀝니다 — 승인 전에 결과물이 먼저 공개돼버리는 걸 막기 위한 설계입니다.

05 자주 발생하는 오류 해결

증상원인 · 해결
봇이 아무 반응이 없다탭 03의 9단계 PowerShell 창이 열려 있는지 확인. 닫혀 있으면 node scripts/start-services.mjs로 다시 실행

창을 열자마자 포트 8787 사용 중 같은 메시지가 뜨고 꺼진다이미 다른 창이나 자동 기동(install-autostart.ps1)으로 서비스가 떠 있습니다. 새로 또 띄우지 말고 기존 것을 그대로 쓰거나, 확실히 다 종료한 뒤 다시 실행하세요
"봇 여러 개가 같은 토큰" 비슷한 에러봇 4개가 진짜 서로 다른 토큰인지 확인

방에서 완료 승인·보완 요청 버튼을 못 찾겠다정상입니다 — 그 두 버튼은 방이 아니라 협업 운영센터에 있습니다. 봇 메뉴의 /center 또는 작업 메시지 링크로 여세요(탭 04 참고)
