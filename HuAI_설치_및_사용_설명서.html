텔레그램 비공개 그룹방 하나가 "AI 업무 지휘소"가 됩니다. 방에서 사람 말투로 지시하면 AI(Claude·Codex)가 실제로 파일을 만들고 고치고, 결과를 방에 보고하고, 방장이 승인 버튼을 눌러야 최종 확정됩니다.

시작 전 체크리스트

아래 6가지가 필요합니다. 전부 무료로 시작할 수 있습니다.

  • ✓
    Windows PC 1대 — AI가 실제로 코드를 실행하는 곳. 설치 후에는 이 PC가 켜져 있어야 시스템이 돌아갑니다.
  • ✓
    Node.js — 이 시스템 자체가 Node.js로 만들어져 있습니다.
  • ✓
    Supabase 계정 — 작업 기록·승인 이력·산출물 주소를 저장하는 DB. 무료 플랜으로 충분합니다.
  • ✓
    Telegram 계정 + 봇 4개 — 사람이 지시하고 결과를 받는 화면.
  • ✓
    Vercel 계정 + Vercel CLI — AI가 만든 웹 결과물을 인터넷에 올려 폰에서 열어보는 용도. 무료 플랜으로 충분하고, CLI 설치·로그인은 탭 03의 8단계에서 합니다.
  • ✓
    Claude Code · Codex CLI 로그인 — 실제로 파일을 읽고 고치는 실행 엔진입니다. 이 PC에 설치하고 로그인까지 해둬야 작업이 실행됩니다(이미 설치돼 있다면 넘어가도 됩니다).
예상 소요 시간: 처음이면 30~50분 정도 걸립니다. 대부분 "계정 만들고 값 복사해서 붙여넣기"입니다. 탭 01 → 02 → 03 순서로 그대로 따라가면 됩니다.
01 PC 준비

PC 준비 — Node.js와 시스템 파일

이 PC에 시스템이 돌아갈 재료를 받는 단계입니다.

1단계 — Node.js 설치

  1. nodejs.org에 접속합니다.
  2. "LTS"라고 적힌 버전을 다운로드합니다(권장 버전).
  3. 설치 파일을 실행하고 나오는 화면에서 전부 "Next"만 눌러 설치를 끝냅니다.

확인: Win 키 → PowerShell 입력 → 엔터로 엽니다. 그 창에 아래를 치고 엔터:

node --version

v24로 시작하는 숫자가 나오면 성공입니다.

2단계 — 시스템 파일 받기

git을 쓸 줄 알면:

git clone https://github.com/SUNWOONGKYU/HuAIChatroomSystem.git C:\Dev\HuAIChatroomSystem

git을 모르면(ZIP으로):

  1. GitHub 저장소 페이지 접속 → 초록색 Code 버튼 → Download ZIP
  2. 다운로드된 zip을 오른쪽 클릭 → "압축 풀기" → C:\Dev\HuAIChatroomSystem 같은 기억하기 쉬운 경로에 풀기 (한글·공백 없는 경로 권장)

3단계 — 필요한 부품 설치 + 빌드

PowerShell에서 방금 그 폴더로 이동한 뒤 아래 3줄을 순서대로 칩니다.

cd C:\Dev\HuAIChatroomSystem
npm install
npm run build
npm install은 1~3분 걸립니다. 중간에 빨간 글씨가 좀 보여도 마지막에 에러 없이 끝나면 괜찮습니다.
02 Supabase 데이터베이스

Supabase 프로젝트 만들기

이 시스템은 "누가 뭘 시켰고, 누가 승인했고, 결과물이 뭔지"를 전부 DB에 기록합니다. 텔레그램 메시지는 화면일 뿐이고, 공식 기록은 여기(Supabase)입니다.

1
가입 · 프로젝트 생성

supabase.com 접속 → 회원가입(구글 계정 가능) → New Project → 이름·비밀번호(꼭 메모)·지역 입력 → Create

2
URL·키 복사

왼쪽 톱니바퀴(Project Settings) → API → Project URL과 service_role 키를 메모장에 복사

3
DB 스키마 적용

왼쪽 메뉴 SQL Editor → New query → supabase/schema.sql 전체 내용을 복사해 붙여넣고 Run

⚠️ service_role 키는 이 시스템 전체를 조작할 수 있는 열쇠입니다. 남에게 보여주거나 인터넷(GitHub 등)에 올리면 안 됩니다.
03 텔레그램 봇과 실행

텔레그램 연결, 설정 채우기, 실행

봇 4개를 만들고, 값을 한 파일에 모으고, 서비스를 켜는 마지막 구간입니다.

4단계 — 텔레그램 봇 4개 만들기

이 시스템은 봇 1개가 아니라 4개(소대장·클로드·코덱스·감사관 역할)를 씁니다.

  1. 텔레그램에서 BotFather(공식 파란 체크 봇)를 검색해 대화를 엽니다.
  2. /newbot 전송 → 봇 이름(아무거나) → 봇 username(반드시 bot으로 끝나야 함) 순서로 입력합니다.
  3. 성공하면 긴 토큰 문자열을 줍니다 — 메모장에 복사하고 어느 역할인지 표시해둡니다.
  4. 이 과정을 4번 반복: LeaderBot(소대장) · ClaudeBot · CodexBot · AuditBot(감사)
⚠️ 4개는 반드시 서로 다른 봇(다른 토큰)이어야 합니다. 봇 1개로 4역할을 흉내내는 방식이 아닙니다.

5단계 — 비공개 그룹 만들고 봇 초대

쉽게 말하면: 방을 만들고, 그 "방 번호"와 "내 번호"를 시스템에 알려주는 단계입니다 — 시스템이 "어느 방에서, 누가" 말했는지 구별하는 데 씁니다.

  1. 텔레그램에서 새 그룹(비공개)을 만들고 봇 4개를 전부 초대합니다.
  2. 그룹 chat_id(방 번호) 알아내기: 그룹에 아무 메시지("테스트")를 보낸 뒤, 브라우저에서 https://api.telegram.org/bot<봇토큰>/getUpdates 를 엽니다. <봇토큰> 자리에는 4개 중 아무 봇의 토큰이나 넣으면 됩니다(같은 방이라 어느 봇으로 봐도 chat_id는 같습니다). 헷갈리면 LeaderBot 토큰을 쓰세요. 이때 그냥 “테스트”라고만 보내면 안 됩니다 — 텔레그램 봇은 기본적으로 그룹의 일반 대화를 못 읽습니다(개인정보 보호 설정). @내봇이름 테스트처럼 봇을 지목해서 보내야 getUpdates에 잡힙니다. 그래도 "result":[]처럼 비어 있으면 봇을 한 번 더 지목해 보내고 새로고침하세요. "chat":{"id": 뒤에 나오는 숫자(보통 -로 시작)가 chat_id입니다.
  3. 내 user_id(내 번호) 알아내기: 텔레그램에서 @userinfobot을 검색해 아무 메시지나 보내면 숫자 id를 알려줍니다. 이 값이 "방장 권한"의 기준입니다 — 승인 버튼은 이 id를 가진 사람만 누를 수 있습니다.

6단계 — 설정 파일 채우기

쉽게 말하면: 지금까지 여기저기서 복사해둔 값들을 파일 한 장에 모아 붙여넣는 단계입니다. 아래 표는 "이 빈칸엔 이 값" 대응표일 뿐이니, 항목 이름이 낯설어도 왼쪽 줄이 어디서 나온 값인지만 따라가면 됩니다.

  1. .env.operation.example 파일을 복사해 이름을 .env.operation.local로 바꿉니다.
  2. 메모장으로 열어 아래 표의 값을 채웁니다.
항목어디서 가져오는 값
SUPABASE_URL탭 02의 Project URL
SUPABASE_SERVICE_ROLE_KEY탭 02의 service_role 키
BOT_SERVICE_TELEGRAM_CHAT_ID위 그룹 chat_id(방 번호)
BOT_SERVICE_OWNER_TELEGRAM_USER_ID위 내 user_id(내 번호)
BOT_SERVICE_PLATOON/CLAUDE/CODEX/AUDITOR_BOT_TOKEN봇 4개 토큰 (각각)
BOT_SERVICE_PLATOON/CLAUDE/CODEX/AUDITOR_BOT_USERNAME봇 4개의 사용자명 (각각) — 5단계에서 지은 이름에서 앞의 @를 뺀 것. 예: @my_leader_chatroom_bot → my_leader_chatroom_bot
⚠️ ..._BOT_USERNAME 4개는 반드시 채워야 합니다. 비워두면 7단계에서 missing-env:BOT_SERVICE_PLATOON_BOT_USERNAME 같은 영어 오류로 멈추고, 예시값(your_platoon_bot)을 그대로 두면 오류 없이 잘못된 이름이 그대로 등록됩니다.

BOT_SERVICE_RECEIVE_MODE=polling 인지 확인합니다(없으면 추가) — 이렇게만 해두면 별도 인터넷 주소 설정 없이 이 PC가 텔레그램과 알아서 연결됩니다, 가장 간단한 방식입니다. LOCAL_GATEWAY_ALLOWED_ROOTS도 2단계에서 받은 폴더 경로로 맞춥니다(이 시스템이 손댈 수 있는 폴더를 정해두는 항목입니다).

⚠️ .env.operation.local은 절대 GitHub에 올리거나 남에게 보내면 안 됩니다. 비밀번호나 다름없는 값들이 들어있습니다.

7단계 — 이 방을 시스템에 등록하기

쉽게 말하면: "이 텔레그램 방 = 이 컴퓨터의 이 폴더"라고 시스템에 한 번 알려주는 단계입니다. 아래 명령어를 그대로 복사해서 붙여넣으면 됩니다 — 내용을 몰라도 됩니다.

먼저 이 방만의 고유 이름표(UUID, 아무 뜻 없는 랜덤 번호)를 하나 만듭니다:

node -e "console.log(crypto.randomUUID())"

화면에 3f2b9c1e-... 같은 긴 문자열이 하나 나옵니다. 이걸 복사해 두세요.

아래 명령의 <...> 세 자리를 실제 값으로 바꿔 실행합니다:

바꿀 자리넣을 값
<room-id>바로 위에서 만든 UUID 문자열
<chat-id>5단계에서 알아낸 그룹 chat_id (보통 -로 시작하는 숫자)
<owner-id>5단계에서 알아낸 내 user_id 숫자
node --env-file=.env.operation.local scripts/generate-supabase-room-seed.mjs --room-id <room-id> --chat-id <chat-id> --owner-id <owner-id> --project-path "C:\Dev\HuAIChatroomSystem"
⚠️ 맨 앞의 --env-file=.env.operation.local을 빼면 안 됩니다. 이게 없으면 6단계에서 채운 값을 못 읽어 missing-env:BOT_SERVICE_PLATOON_BOT_USERNAME 오류로 멈춥니다.

출력된 SQL 전체를 복사해 Supabase SQL Editor에 붙여넣고 Run 합니다.

8단계 — Claude Code / Codex / Vercel 로그인 확인

이 PC에 Claude Code와 Codex CLI가 설치되고 로그인돼 있어야 실제 작업 실행이 됩니다 — 방에서 승인을 눌러도 이 둘이 없으면 실행이 실패합니다. 웹 페이지를 만드는 작업을 쓸 거라면 Vercel CLI도 필요합니다(시스템이 배포할 때 이 PC의 vercel 명령을 그대로 호출합니다).

먼저 이미 깔려 있는지 확인합니다. PowerShell에서:

claude --version
codex --version
vercel --version

셋 다 버전 숫자가 나오면 설치는 끝난 것이니 로그인 여부만 확인하고 넘어갑니다. 인식할 수 없는 명령 류의 오류가 나오는 쪽만 아래대로 설치합니다.

도구설치로그인
Claude Codenpm install -g @anthropic-ai/claude-codeclaude 를 실행하면 브라우저가 열리며 로그인 안내가 나옵니다
Codex CLInpm install -g @openai/codexcodex login 실행 후 브라우저에서 ChatGPT 계정으로 로그인
Vercel CLInpm install -g vercelvercel login 실행 후 브라우저에서 로그인

공식 안내: Claude Code 문서 · Codex CLI 저장소. 설치 방법은 각 도구 쪽에서 바뀔 수 있으니, 위 명령이 안 되면 공식 안내를 따르세요.

이 시스템은 실행 엔진을 3종(Claude Code · Codex · Antigravity)까지 쓸 수 있지만, 2종만 있어도 정상 작동합니다. Antigravity는 앞의 둘이 동시에 한도에 걸린 드문 경우에만 쓰이는 예비 엔진이라 설치하지 않아도 되고, 없으면 시스템이 "실행 프로그램을 찾지 못했습니다"라고 방에 알리고 멈춥니다.

9단계 — 서비스 실행

PowerShell 창을 1개 열고 아래를 실행합니다. 이 명령 하나가 .env.operation.local을 읽어들이고 bot-service와 local-gateway 둘 다 띄워주며, 하나가 죽으면 자동으로 다시 올립니다.

cd C:\Dev\HuAIChatroomSystem
node scripts/start-services.mjs

창에 두 서비스가 떴다는 로그가 나오고 멈추지 않고 계속 떠 있으면 정상입니다. PC가 켜져 있는 동안 이 창이 계속 열려 있어야 시스템이 작동합니다.

⚠️ node dist/apps/bot-service/src/cli.js처럼 서비스를 직접 실행하지 마세요. 그렇게 하면 .env.operation.local이 읽히지 않아서, 파일을 아무리 정확히 채웠어도 창이 열리자마자 missing-env:SUPABASE_URL 같은 오류를 내고 꺼집니다. 반드시 위의 scripts/start-services.mjs로 켜세요.

승인현황판완료를 승인합니다 — 이때 웹 산출물이 정식 주소로 승격됩니다
보완 요청현황판결과가 부족할 때 작업자에게 보완을 요청합니다
방에는 완료를 승인하는 버튼이 없습니다. 작업을 시작시키는 결정(실행·수정·반려)만 방에서 하고, 끝난 뒤의 결정(승인·보완 요청)은 전부 현황판에서 합니다. 방에서 아무리 찾아도 없는 게 정상입니다. 현황판의 완료 버튼 이름은 「완료 승인」이 아니라 그냥 「승인」입니다.
자동허용 — 파일을 전혀 안 바꾸는 조회·분석·설명성 지시는 "실행" 버튼 자체가 뜨지 않고 바로 시작됩니다(방에 "🟢 자동 시작" 안내만 뜹니다). 판단이 애매하면 시스템은 항상 안전한 쪽(승인 필요)으로 처리합니다.

결과 확인하기

작업이 끝나면 방에 결과가 옵니다. 300자가 넘는 긴 보고는 앞부분만 방에 오고 [전문 보기] 버튼이 붙습니다 — 눌러서 현황판에서 전체를 봅니다. 현황판은 방에 고정된 링크나 /tasks 명령으로 엽니다.

완료 승인하기

작업이 끝나면 현황판에서 [승인] 버튼을 누릅니다(방 안에는 이 버튼이 없습니다). 결과물이 있으면 현황판 상세의 「결과물」 목록에 링크로 표시되니, 승인 전에 눌러서 먼저 확인하세요.

퀴즈가 뜰 수 있습니다 — 파일을 실제로 바꾼 작업은 완료 승인 전에 "뭐가 바뀌었는지 이해했는지" 확인하는 객관식 3문항이 먼저 나옵니다(인지부채 방지 장치). 통과해야 완료 승인 버튼이 나옵니다.
웹 페이지를 만든 작업이라면 — 완료 승인 전에는 산출물 링크가 "프리뷰"(아직 정식 주소 아님) 상태입니다. 완료 승인을 누르는 순간 그 링크가 정식(프로덕션) 주소로 바뀝니다 — 승인 전에 결과물이 먼저 공개돼버리는 걸 막기 위한 설계입니다.

그 밖의 명령어

/tasks                작업 목록
/task <task_id>       작업 하나 상세
/search <단어>         작업 검색
/trace <task_id>      이벤트·산출물·검증 이력
@my_audit_chatroom_bot 이 작업을 보안 검토해줘   (감사관에게 직접 요청)
05 문제 해결 · 자주 걸리는 오류

문제가 생기면

처음 설치할 때 가장 자주 걸리는 것부터 정리했습니다.

증상원인 · 해결
봇이 아무 반응이 없다탭 03의 9단계 PowerShell 창이 열려 있는지 확인. 닫혀 있으면 node scripts/start-services.mjs로 다시 실행
npm install에서 멈추거나 에러인터넷 연결 확인 후 다시 실행. 안 되면 Node.js를 v24 LTS로 재설치
창을 열자마자 바로 꺼진다 — missing-env:...① 서비스를 node dist/...cli.js로 직접 켜지 않았는지 확인 — 반드시 node scripts/start-services.mjs로 켜야 .env.operation.local이 읽힙니다. ② 그래도 같으면 오류에 찍힌 이름(예: BOT_SERVICE_PLATOON_BOT_USERNAME)이 .env.operation.local에 채워져 있는지 확인 — 봇 토큰 4개·사용자명 4개·Supabase URL/키가 자주 빠집니다
"봇 여러 개가 같은 토큰" 비슷한 에러봇 4개가 진짜 서로 다른 토큰인지 확인
승인 버튼을 눌러도 반응이 늦다정상입니다 — 실제 AI 실행은 몇 초~몇 분 걸립니다. 방에 "⏳ 작업 중" 표시가 주기적으로 올라옵니다
Supabase SQL 실행에서 에러supabase/schema.sql 전체를 빠짐없이 붙여넣었는지 확인(일부만 붙여넣으면 실패)
방에서 완료 승인·보완 요청 버튼을 못 찾겠다정상입니다 — 그 두 버튼은 방이 아니라 현황판에 있고, 이름도 승인·보완 요청입니다. 방에 고정된 [작업 현황판 열기] 버튼이나 /tasks 명령으로 현황판을 여세요(탭 04 참고)
승인은 됐는데 실행이 안 되거나 이상한 에러가 난다이 PC에 Claude Code·Codex CLI가 로그인돼 있는지 확인(탭 03의 8단계). 로그인 세션이 끊기면 실행이 실패합니다
이 표에 없는 문제는 탭 06 참고자료의 GITHUB_QUICKSTART.md(더 기술적인 버전)와 OPERATION_STATUS.md(현재 알려진 이슈 목록)를 참고하세요.

시스템 관계도

구성 요소 자세히 보기

탭 00에서 "AI 여러 명이 각자 맡은 역할대로 일한다"고 뭉뚱그려 말한 그 안쪽입니다 — 이 시스템을 이루는 조각들이 정확히 뭘 하는지입니다.

방
텔레그램 방

사람이 지시하고 결과를 받는 화면. 이 시스템의 유일한 사용자 인터페이스입니다.

L
LeaderBot(소대장)

사람 말을 읽고 "이건 질문인지 작업인지" 먼저 판단합니다. 작업이면 목적·범위·완료조건을 갖춘 제안으로 정리해 방에 올립니다.

C
ClaudeBot · CodexBot

실제로 코드를 읽고 파일을 만들거나 고치는 실행자입니다. 내부적으로 Claude Code·Codex·Antigravity 세 실행 엔진을 쓰고, 하나가 사용 한도에 걸리면 다른 엔진이 이어받습니다(최대 2번 인계).

A
AuditBot(감사)

실행자와 다른 엔진이 결과물을 독립적으로 다시 검토합니다 — 만든 사람이 자기 결과를 자기가 검사하지 않게 하기 위해서입니다.

B
bot-service

텔레그램과 이 시스템을 연결하는 통로. 누가 말했는지 확인하고, 권한을 검사하고, 답을 다시 텔레그램으로 보냅니다.

G
local-gateway

내 PC 안에서 실제로 명령을 실행하는 부분. 허락된 폴더 밖은 절대 건드리지 않습니다.

D
Supabase

"누가 뭘 시켰고 누가 승인했는지"를 남기는 공식 기록 창고. 텔레그램 메시지가 지워져도 여기 기록은 남습니다.

V
Vercel

AI가 만든 웹페이지를 인터넷 주소로 올려 폰에서 바로 열어볼 수 있게 하는 곳.

기술 용어 풀이

본문에 나온 낯선 단어들만 모았습니다. 몰라도 시키는 대로 따라가면 되지만, 궁금할 때 여기서 찾아보세요.

용어쉬운 뜻
chat_id텔레그램 그룹방 하나하나에 매겨진 고유 번호(방 번호)
user_id텔레그램 사용자 한 명 한 명에게 매겨진 고유 번호(내 번호)
토큰(token) / 키(key)"이 계정·이 봇은 나다"를 증명하는 긴 비밀번호 같은 문자열
UUID세상에서 겹칠 일이 거의 없는 랜덤 고유 번호. 여기서는 "이 방"을 구별하는 이름표로 씁니다
환경변수 / .env 파일프로그램이 시작할 때 읽어가는 설정값 모음 파일. 여기에 계정 정보·키를 적어둡니다
PowerShell윈도우에서 글자로 명령을 내리는 검은(또는 파란) 화면 프로그램
npm install / npm run build"필요한 부품 받기" / "실행 가능한 형태로 조립하기" 명령어
배포(deploy) / 프로덕션(production)결과물을 실제로 인터넷에 올려 아무나 열어볼 수 있는 정식 주소로 만드는 것
프리뷰(preview)아직 정식 주소가 아닌, 미리 볼 수만 있는 임시 주소
SQL데이터베이스에 "이런 표 만들어줘/이런 값 넣어줘"라고 지시하는 명령어 언어
